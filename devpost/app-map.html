A quick map of the working app

Outranka

Outranka compares a submitted draft or web page with Google organic results for a keyword and region. It returns content recommendations, quality checks, competitor details, and a downloadable report; signed-in users can revisit saved audits.

One audit, from input to result

Reference route through the code

This route is a guide to the source; it does not imply that someone has completed an interactive code tour.

1

Start where the user acts

app/page.tsx → Home component, handleSubmit. The form data is posted to /api/analyze; the response is kept in session storage before navigating to results.

2

Find the matching rule

lib/rankingMatch.ts → findSiteRankings. It separates an exact URL match from other top‑10 pages on the normalized hostname, treating www/non‑www and tracking parameters as equivalent.

3

Find the visible outcome

app/results/page.tsx → ResultsPage. It displays the exact rank and any other matching pages. The report export path starts at lib/downloadReport.ts → buildAnalysisMarkdown.

To change this, start here

  • Input fields and URL/text choice — components/InputForm.tsx
  • Google results and result selection — lib/serp.ts
  • Page-vs-domain match behavior — lib/rankingMatch.ts
  • E‑E‑A‑T text indicators — lib/eeat.ts; report card — components/report/tabs/ContentUxTab.tsx
  • Report content and PDF generation — lib/downloadReport.ts and app/api/report/pdf/route.ts
  • Past audit list — app/audits/page.tsx

A practice to reuse

Turn an ambiguous feature into observable cases before changing code. For ranking detection, “does my page rank?” became two cases—exact submitted URL and another page on the same hostname—implemented in lib/rankingMatch.ts and app/results/page.tsx. On another project, write down the positive case, the near-miss case, and what the user should see before choosing where to implement the logic.

The production build passed, which checks compilation and types; it does not replace a live SERP test with a domain whose pages appear in the results.

Run it again

From the project folder, run npm run dev and open http://localhost:3000. Local analysis needs the environment variable names listed in .env.example; put real credentials only in ignored .env.local, never in this map.
